Getting Started · v0.1.0

Get Guppty on your machine

Guppty is a small language I wrote in Rust. You write programs in .gup files, compile them to bytecode, and run them from the terminal.

Install Recommended

One command. Rust is installed only if you don't already have it.

Terminal
$curl -fsSL https://raw.githubusercontent.com/adrian-1-cardona/guppty/main/install.sh | bash

Paste this in Terminal. The script checks for Rust, builds guppty, and leaves it on your PATH. You only run it once.

Build from source Clone the repo and install with Cargo

Prefer to clone and build it yourself? Pick your OS, then follow the steps. You'll need Git and Rust.

  1. Install Rust with rustup. Restart your terminal when it finishes so cargo is on your PATH.

    curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

  2. Clone the repo from GitHub.

    git clone https://github.com/adrian-1-cardona/Guppty.git

  3. Move into the project folder.

    cd Guppty

  4. Install the guppty command. Cargo puts it in ~/.cargo/bin.

    cargo install --path .

  5. Run an example to make sure everything works.

    guppty examples/program.gup

First Run

Quick Start

← Back to install

After install, guppty stays on your machine. Use these three commands whenever you want to write something new.

1

Create a program

Scaffolds a starter hello.gup file in your current folder.

guppty new hello
2

Compile it

Checks your code for errors without running it. Good habit before you execute.

guppty compile hello.gup
3

Run it

Compiles to bytecode and runs on the VM. Edit your file, save, run again.

guppty hello.gup

Terminal

CLI Commands

After install you get a small toolkit. Create a .gup file, compile it to catch errors early, then run it. Most of the time you'll just do guppty yourfile.gup.

Add --interp to use the tree-walking interpreter instead of the VM. Both should give the same output — the flag is there if you want to compare backends.

guppty new

Creates a starter .gup file in the current folder.

guppty new hello

guppty compile

Compile-check without running. Shows bytecode size or a readable error.

guppty compile hello.gup

guppty run

Compile and execute on the VM. You can also just pass the file path.

guppty hello.gup

--interp flag

Run through the tree-walking interpreter instead of the VM.

guppty hello.gup --interp

guppty help

Lists all subcommands and usage.

guppty help

cargo run (dev)

When working on Guppty itself — run without reinstalling the binary.

cargo run -- examples/program.gup

Project

What Is Guppty?

Guppty is a small indentation-based language I built from scratch in Rust. You write .gup files, and Guppty turns that text into something your computer can run — with every step visible in the source code.

It's not trying to replace Python or Rust. It's meant to be simple enough to learn from and pleasant enough to extend. The whole project fits in one crate with clearly named files, so you can actually read through it in an afternoon.

You get variables, arithmetic, strings, booleans, if/else, while and for loops, functions, recursion, and closures. No curly braces — just indent your blocks like Python.

There are two ways to run programs: a bytecode compiler + stack VM (the default), and a tree-walking interpreter (via --interp). Both should match for correct programs. The examples in examples/ double as integration tests — if you break something, the tests catch it.

Performance

Benchmarks

Having two backends in one project means you can compare them. I ran recursion_fib.gup 200 times in release mode and averaged the wall-clock time (startup + file I/O + lex + parse + compile/interpret + execute).

VM (compile + run) 2.69 ms
Tree-walker (--interp) 2.64 ms

At this scale the difference is basically noise — the program is tiny, so startup and file reading dominate. The point is the infrastructure exists: as programs get bigger, the VM should pull ahead because it runs precompiled bytecode instead of re-walking the AST every time.

Purpose

Why I Built It

The world doesn't need another production language. Guppty exists because I wanted to answer a simple question: what actually happens when you type text into a file and tell a computer to run it?

Most of us use languages every day without looking under the hood. That's fine for getting work done. But if you've ever been curious about how a language works — from raw text to executed instructions — Guppty gives you a complete, readable implementation to study.

I kept it small on purpose. When the whole codebase fits in your head, you can add a keyword and trace it through the lexer, parser, compiler, and VM in one sitting. That's the kind of feedback loop that actually builds intuition.

Under the Hood

How It Works

Guppty is Rust 2021 with zero external runtime dependencies. The core pipeline is textbook compiler architecture, but small enough to read in an afternoon.

Source.gup file
Lexertokens
ParserAST
Compilerbytecode
VMstdout

The lexer turns characters into tokens (and tracks indentation). The parser builds an AST. The compiler emits bytecode. The VM executes it on a stack. Pass --interp to skip compilation and walk the AST directly instead.

Rust 2021

Fast native binary, strong types for tokens/AST/bytecode, and Cargo for tests and builds. No external crates in the core — every line is hand-written.

Stack VM

The default backend. Compiles to bytecode first, then executes on a value stack + call frames. Same idea as Java, Python, or Lua VMs.

Tree Interpreter

The --interp path. Walks the AST node by node. Simpler to understand, good as a reference to verify the compiler.

Integration Tests

Run real .gup programs and compare stdout to expected output files. Docs and tests stay in sync because they're the same examples.

Notes

What I Learned

Building even a tiny language teaches you things you can't get from a textbook alone. Here's what stuck with me:

Everything connects. Add one keyword and you touch the lexer, parser, compiler, VM, an example program, and a test. What looks like a small change ripples through the whole codebase — and that's the point.

Examples are tests. The examples/ folder looks like demos, but it's also the test suite. Break a feature and a test fails. Add a feature and you write a demo at the same time.

Error messages matter. A language can have great syntax, but if errors are cryptic, people won't use it. I spent real time on clear messages with file:line:column, a caret, and a help: line telling you how to fix it.

Language

Syntax Indentation based

Guppty uses indentation for blocks — no curly braces or semicolons. Indent the lines that belong inside an if, loop, or function, and the parser figures out the structure.

Variables are created by assignment — no let or var. You get integers, floats, strings, chars, booleans, and arrays. Use out() to print anything.

Variables and output

Assign values to names and print them with out(). No type annotations needed.

x = 5
name = "Guppty"
ready = true
letter = 'g'
out(name)
out(x + 10)

If, while, and for

Indent the body under the keyword. for uses range(1 through 3) for iteration bounds.

score = 85
if score >= 80
    out("You passed!")
else
    out("Keep studying!")

for i in range(1 through 3)
    out(i)

Functions

Write the name and params on one line, indent the body. Use return to send a value back.

add(a, b)
    return a + b

out(add(2, 3))

Closures

Define a function inside another and return it. The inner function remembers variables from the outer scope.

makeAdder(x)
    addIt(y)
        return x + y
    return addIt

adder = makeAdder(5)
out(adder(3))

Comments

Double-slash comments, same as C, Java, or Rust. Everything after // on a line is ignored.

// this is a comment
out(42) // inline comment

Programs

Examples

The examples/ folder has runnable programs for every feature. Each one has a matching file in examples/expected/ with the exact output it should produce.

Hello World

The shortest possible Guppty program.

out("Hello World!")
guppty examples/hello.gup

Recursion

Factorial with a recursive function. Works on both the VM and interpreter.

factorial(n)
    if n <= 1
        return 1
    return n * factorial(n - 1)

out(factorial(5))
guppty examples/recursion_factorial.gup

Closure Counter

A counter that keeps its own state through a captured variable.

makeCounter(start)
    count = start
    increment()
        count = count + 1
        return count
    return increment
guppty examples/closure_counter.gup

Community

Contribute

Guppty is open source and I welcome contributions — bug fixes, new features, better errors, docs, whatever. The codebase is small enough that you can get oriented in an afternoon.

Fork the repo, make a branch, run cargo test, and open a pull request. Keep PRs focused on one thing. If you add a language feature, include an example .gup file and an expected output file so it becomes a test automatically.

Help

Common Issues

Most setup problems come down to a missing tool on your PATH or a fresh terminal session. Here's what I see most often:

Installer failed

You need curl (macOS/Linux) or PowerShell (Windows) and network access. If Rust was just installed, open a new terminal and try again so ~/.cargo/bin is on your PATH.

cargo or rustc not found

The one-line installer handles Rust for you. If installing manually, get it from rustup.rs and restart your terminal.

guppty not found after install

The binary lives in ~/.cargo/bin (or C:\Users\You\.cargo\bin on Windows). Check your PATH, or run source "$HOME/.cargo/env" and try again.

Can't read my file

Create one with guppty new my_program, or pass the full path: guppty ./my_program.gup.

Indentation looks wrong

Don't mix tabs and spaces. Use four spaces per level — that's what the examples use. One line at the wrong indent level can confuse the parser.

How do I verify everything works?

Run guppty compile hello.gup on your own program, or cargo test from a source checkout.
